## 0. What “Githi” is (do not confuse trees)

| Tree | Path | What it is |
|------|------|------------|
| **Source product** | `Downloads/githi` (`src/githi/{agent,harness,tools,llm,memory,sandbox,…}`) | Standalone agent — loop, prompt, tools, skills, local memory/sandbox already defined |
| **Platform host** | `prime-agent-study-main/.../services/supervisor/.../runtimes/githi/` | Githi adapted as an `AgentRuntime` plug-in inside supervisor |
| **Sibling services** | `services/{model-gateway,memory}/`, sandbox providers | Where monolith `llm/` / `memory/` / isolation move over time |
| **This folder** | `development/githi-to-services-migration/` | Port diaries + M0 index — **not** the agent source |

Migration does **not** invent loop/prompt/subagents from scratch. It **hosts** capabilities that already exist in `Downloads/githi` behind catalog, gateway, journal, auth, and the Lab BFF. Completing migration = those hosts are Dn-PASS green, not rewriting Phase summaries.
