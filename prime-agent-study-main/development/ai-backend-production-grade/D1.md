# D1 — Service auth & identity

**Status:** AI plane largely production-ready (supervisor service JWT + gateway fail-closed); system BFF outbound mint + memory HTTP auth still open  
**Wave:** 0 (blocking — do before sessions, tools, memory, workspace)  
**Goal:** System backend is the only trusted caller of the AI backend. Tenant/principal come from verified service identity, not client-spoofable headers. Browser never talks to AI with user JWTs.

**Done means (north star):**

> System → AI uses service JWT (or mTLS). Tenant/principal are minted by the system backend after user auth. AI services refuse unauthenticated or impersonating callers in production.

---

## 1. Why D1 exists

Harness Lab UX (Test chat, Sessions, Traces, Tools, Memory) must eventually run through:

```text
Browser ──user JWT──► System backend (prime_agent)
                           │
                           ├─ validate user / RBAC / ownership
                           ├─ map User → {tenant_id, principal_id}
                           └─ service credential
                                  │
                                  ▼
                           AI plane (supervisor → gateway → memory)
```

Until D1 is closed, any network peer can assert `X-Tenant-Id` / `X-Principal-Id` (and often call gateway/memory with no auth). Later dimensions (workspace grants, sandbox, memory) cannot be trusted on top of that.

**UI surfaces that depend on D1**

| UI | Why auth matters |
|----|------------------|
| Login / profile / team | System owns human identity; AI must receive mapped principal only |
| Harness Test / Sessions / Traces | Session create must be tenant-bound to the logged-in user |
| Tools / Memory | Invoke & recall must not cross tenants |
| Settings (API keys, budget) | Secrets stay on system; AI gets service identity only |

---

## 2. Architecture rule (freeze this)

| Party | Trust |
|-------|--------|
| Browser / SPA | Untrusted for AI identity |
| Sandbox / agent process | Untrusted for authz |
| System backend (BFF) | Trusted mapper + minter of AI credentials |
| Supervisor / gateway / memory | Verify service credentials; never trust raw client headers in prod |

**Hard rules**

1. User JWT (`aud=prime-agent-web`) **stops at the system backend**.
2. AI sees only **service** credentials + verified `tenant_id` / `principal_id`.
3. Production profiles **fail closed** if auth is unset.
4. `/healthz` (and optionally `/readyz`) may stay public for probes; `/v1/*` and `/metrics` must not be open in prod.

## 3. What exists today

### 3.1 System backend (`backend/prime_agent/`) — strong for humans, empty for AI

| Capability | Status | Evidence |
|------------|--------|----------|
| Register / login / refresh / logout | Done | `web/routes/auth.py` |
| Access JWT (HS256, `aud=prime-agent-web`) | Done | `services/auth_service.py`, `web/dependencies/jwt_manager.py` |
| Refresh: opaque, hashed, rotation + family revoke | Done | `db/models/refresh_token.py` |
| HttpOnly refresh cookie + CSRF double-submit | Done | auth routes + `web/dependencies/csrf.py` |
| Roles `owner \| admin \| member` from DB | Done | `web/dependencies/auth.py` |
| Owner-scoped harness/tool CRUD | Done | harness/tool routes |
| Outbound AI client | **Missing** | No supervisor URL / service token in settings |
| User → tenant/principal mapper | **Missing** | No tenant tables; only `users.id` |
| Mint service JWT / mTLS to AI | **Missing** | — |

Frontend auth client (`frontend/src/lib/api/client.ts`) already targets system only (`withCredentials`, bearer, CSRF refresh). That is correct for D1 — do not put AI URLs or `AUTH_TOKEN` in `NEXT_PUBLIC_*`.

### 3.2 Supervisor — stub inbound auth

| Capability | Status | Evidence |
|------------|--------|----------|
| Optional shared `AUTH_TOKEN` | Stub | `config.py`, `api/deps.py` |
| Tenant from `X-Tenant-Id` | Spoofable | `current_tenant` returns header as-is |
| Principal from `X-Principal-Id` (else tenant) | Spoofable | `current_principal` |
| Per-tenant rate limit / quotas | After trust | `policy/rate_limit.py`, `policy/quotas.py` |
| Session rows filtered by `tenant_id` | App-level | `session/manager.py` |
| Workspace grant seam (`AuthzService`) | Real but unused on HTTP | `seams/authz*.py`; factory = **memory** only |
| JWT / OIDC / mTLS inbound | **Missing** | No verifier deps |
| Deploy secrets for `AUTH_TOKEN` | **Missing** | ESO has gateway/DB only |

Key behavior today (`api/deps.py`):

- If `AUTH_TOKEN` unset → **no auth**, only require `X-Tenant-Id`.
- If set → exact string `Bearer {token}` (no expiry, audience, or constant-time compare).
- Staging/root compose often omit `AUTH_TOKEN` → API open to anyone who can set headers.

### 3.3 Model gateway — optional shared secret

| Capability | Status | Evidence |
|------------|--------|----------|
| `MODEL_GATEWAY_TOKEN` optional Bearer | Fail-open when empty | `model_gateway/app.py` `_check_auth` |
| Healthz public | OK for probes | `GET /v1/healthz` |
| Caller identity / tenant | **Missing** | Shared secret only |
| Tests for “auth required” | Partial | `tests/test_gateway.py` |
| Root compose token | Empty string | Auth **off** by default |

Supervisor → gateway: `HttpModelGatewayClient` may send `GATEWAY_TOKEN` / `MODEL_GATEWAY_TOKEN`. Local compose often has URL without matching token.

### 3.4 Memory service — no HTTP auth

| Capability | Status | Evidence |
|------------|--------|----------|
| Tenant/scope required in body | Client-asserted | `memory_service/tenant.py` |
| Bearer / API key / mTLS | **Missing** | `app.py` has no Authorization |
| RLS SQL stub | Not wired | `rls_postgres.sql` (`set_config` never called) |
| IDOR risk | Open | `GET /v1/memory/items/{id}` by UUID alone |
| Bind file from supervisor | URL + scope only | `harness/bind_files.py` — no token field |
| In docker-compose / k8s | Often absent | Gap appears the moment it is added |

### 3.5 Trust map (current)

```text
Browser ──user JWT──► System          ✅ human auth
System  ──(nothing)──► Supervisor     ❌ no client yet
Anyone  ──X-Tenant-Id──► Supervisor   ❌ spoofable / often unauthenticated
Supervisor ──optional Bearer──► Gateway  ⚠️ fail-open if empty
Harness/Supervisor ──no auth──► Memory   ❌ trust network + body scope
```

## 4. What is missing (production-grade checklist)

### Critical (blocks D1)

- [ ] Supervisor production profile: **AUTH_REQUIRED** — refuse boot without verifier
- [ ] Tenant/principal from **verified claims**, not raw `X-*` from arbitrary clients
- [ ] Impersonation-negative tests (tenant A token cannot act as tenant B)
- [ ] System outbound AI client + settings (`AI_SUPERVISOR_BASE_URL`, service credential)
- [ ] System mapper: `User → {tenant_id, principal_id}` (document MVP: e.g. single-tenant-per-user = `user.id`)
- [ ] **Never forward** user JWT to AI (assert in tests)
- [ ] Gateway: fail-closed in non-dev; token required; constant-time compare
- [ ] Memory: service credential on all non-health routes; scope must match claims
- [ ] Deploy: secrets for supervisor auth + gateway + memory in ESO / staging compose

### High (should land with or immediately after D1)

- [ ] Short-lived **service JWT** (`iss=prime-agent-api`, `aud=yal-supervisor`, `type=service`, `tenant_id`, `principal_id`, `exp`) instead of eternal shared `AUTH_TOKEN`
- [ ] Memory bind file / harness client carries `Authorization`
- [ ] `/metrics` authenticated or network-restricted in prod
- [ ] Audit log fields: `service_id`, `tenant_id`, `principal_id` (no secrets)
- [ ] Contract docs updated: auth **required** in production profiles

### Explicitly out of D1 (later dimensions)

| Later | Dimension |
|-------|-----------|
| Postgres `GrantStore` + HTTP `require_grant` | D11 |
| Workspace hydrate authz | D9 / D11 |
| Virtual keys in sandbox (no gateway token in agent env) | D5 / D10 |
| Full OIDC login UI on supervisor | Never — system owns human login |
| Subagent / multi-replica sticky auth | D12 |

## 5. Target design for D1

### 5.1 MVP path (acceptable interim)

1. System validates user JWT as today.
2. System maps user → `{tenant_id, principal_id}`.
3. System calls supervisor with shared `AI_SUPERVISOR_AUTH_TOKEN` + headers it alone sets.
4. Supervisor requires `AUTH_TOKEN` in prod; still accepts headers **only from callers that already passed Bearer** — residual risk: anyone with the shared secret can impersonate any tenant.
5. Network policy: only system pods can reach supervisor `:8080` (mitigates residual risk).

**Document residual risk** until service JWT lands.

### 5.2 Production path (D1 complete)

1. System mints short-lived **service JWT** after user auth (or uses mTLS + JWT).
2. Supervisor verifies signature (`JWKS` or shared HMAC), `aud`, `iss`, `exp`, `type=service`.
3. `tenant_id` / `principal_id` taken **only** from claims; conflicting `X-*` headers → 403 or ignored.
4. Same pattern for gateway (`aud=model-gateway`) and memory (`aud=memory-service`), or mTLS mesh identity plus internal tokens.
5. Memory: body `scope.tenant` must equal claim tenant; IDOR endpoints check membership.

### 5.3 Header / claim contract

| Claim | Source | Used for |
|-------|--------|----------|
| `tenant_id` | System membership / MVP `user.id` | Session rows, quotas, memory scope |
| `principal_id` | `user.id` | Future grants (D11), audit |
| `service_id` | `sub` of service JWT | Audit / metrics |
| `aud` | `yal-supervisor` \| `model-gateway` \| `memory-service` | Audience isolation |

User JWT remains `aud=prime-agent-web` and is **rejected** by AI services.

## 6. Acceptance criteria

### A. Supervisor inbound

- [ ] `AUTH_REQUIRED=true` (or `ENV=production`): process **exits** if verifier not configured
- [ ] Unauthenticated `/v1/*` → **401**
- [ ] Valid service credential for tenant A cannot create/list sessions as tenant B → **403**
- [ ] Spoofed `X-Principal-Id` does not override claim principal
- [ ] Unit/integration tests for the matrix above in CI

### B. System BFF

- [ ] Settings require AI base URL + service credential in production
- [ ] At least one gated proxy path (e.g. AI health or create-session stub) uses `CurrentUser` then service credential
- [ ] Test: AI outbound request contains service auth; **user access token string absent**
- [ ] Service token never returned in JSON/cookies to the browser
- [ ] Existing browser auth tests still pass (refresh, CSRF, family revoke)

### C. Gateway

- [ ] Non-dev: empty `MODEL_GATEWAY_TOKEN` → refuse start or fail-closed middleware
- [ ] Missing/wrong Bearer → 401; healthz stays open
- [ ] Constant-time compare; wrong-token test
- [ ] Compose/staging do not ship empty tokens outside `PROFILE=dev`

### D. Memory

- [ ] Non-health routes require Bearer (or mTLS)
- [ ] Tenant from credential; body scope mismatch → 403
- [ ] Get-by-id enforces tenant (or 404); IDOR test
- [ ] Bind/client sends `Authorization`; `MEMORY_SERVICE_TOKEN` (or JWT) documented

### E. Deploy & contracts

- [ ] ESO / staging secrets include supervisor auth, gateway token, memory token
- [ ] `contracts/model_gateway.md`, `contracts/durable_memory.md`, and a new or updated service-auth note require auth in prod
- [ ] CI fails if production compose profile has empty AI auth secrets

### F. Explicit residual (if MVP shared secret only)

- [ ] README documents: shared `AUTH_TOKEN` + headers = impersonation if secret leaks; network policy required; service JWT is D1.1

## 7. Implementation order (recommended)

1. **Threat model freeze** — paste §2 into a short `contracts/service_auth.md` (or extend existing seams doc).
2. **Supervisor fail-closed config** — `AUTH_REQUIRED` / prod profile.
3. **System settings + `AiClient` stub** — call supervisor `/healthz` or `/readyz` with service Bearer; mapper MVP.
4. **Impersonation tests** on supervisor (headers + token matrix).
5. **Gateway fail-closed + compose secrets** — align `GATEWAY_TOKEN` ≡ `MODEL_GATEWAY_TOKEN`.
6. **Memory Bearer + bind token field** — even before full JWT.
7. **Service JWT** — system mints; supervisor (then gateway/memory) verify claims; drop trust in raw `X-*`.
8. **Deploy/ESO + contract updates + CI gates**.
9. **Hand off to D2** — system refuses “Run” when AI `/readyz` fails.

Do **not** start D4 (sessions UI) against an open supervisor.

## 10. Definition of done

D1 is **done** when:

1. A logged-in Harness Lab user can only reach AI through the system backend.
2. AI services reject anonymous and cross-tenant impersonation in automated tests.
3. Gateway and memory are not usable without service credentials in staging.
4. Residual risks (if any) are written down and time-boxed (e.g. service JWT as D1.1).

Then proceed to **D2** (ready gates) and **D3–D4** (catalog bind + sessions/SSE).
