# D11 — Grants (principal → scope → authz)

**Status:** PASS (2026-08-31) — verify cycle 0; 21/21; next orchestrator advance  
**Wave:** 4 (with or just after D9; after D1 principal trust; before trusting shared scopes in multi-tenant staging)  
**Depends on:** D1 (service JWT `principal_id` — not spoofable headers), D9 (hydrate/sync already call `authorized_*`), D10 (`sandbox:exec` on isolated providers)  
**Goal:** Memberships and grants survive restart in Postgres. HTTP Workspace / presign / admin APIs use `require_grant`. Owner bootstrap and invite/revoke are product-safe. Sandbox and agents never decide authz. Outer “team roles” stay distinct from agent scope grants.

**Done means (north star):**

> After supervisor restart, principal P still has the same grants on scope S. Strangers cannot attach to S or hydrate it. File HTTP and presign fail closed without the right grant. Admin can manage memberships via `scope:admin`. Bootstrap honors `GRANT_STORE=postgres`. Principal identity comes only from verified service claims (D1).

---

## 1. Why D11 exists

D9 gates hydrate/sync and D10 needs `sandbox:exec`, but today grants live in **process memory**:

```text
Principal (D1: service JWT claims — or spoofable X-Principal-Id if auth off)
    → Scope membership
    → Grants (workspace:read|write, sandbox:exec, artifact:download, scope:admin)
    → AuthzService.require
         ├── authorized_hydrate   → workspace:read     ← wired (session)
         ├── authorized_sync      → workspace:write    ← wired (session)
         ├── require_sandbox_exec → sandbox:exec       ← wired (session create)
         ├── HTTP require_grant   → any                ← implemented, unused on routes
         └── presign / admin      → artifact:download / scope:admin  ← enum only
```

Until D11 closes:

| Today | Problem |
|-------|---------|
| `MemoryGrantStore` | Restart loses memberships — shared scopes untrustworthy |
| Bootstrap | **Hardcodes** `create_grant_store("memory")` |
| Alembic `0008` + ORM | Tables exist — **no store reads/writes them** |
| `require_grant` FastAPI dep | Ready — **no route uses it** |
| `artifact:download` / `scope:admin` | Vocabulary + unit tests only |
| HTTP Workspace / membership APIs | **Missing** (D9 parks file API; D11 owns grant matrix) |
| Outer Settings **Team** | Product Owner/Admin/Member **mock** — ≠ Grant enum |
| Principal residual | Auth off → client `X-Principal-Id` (WP-M7 / D1) |

**UI surfaces that depend on D11**

| UI | Need |
|----|------|
| Shared project scopes | Invite member → durable grants |
| Files / download (D9 HTTP) | `workspace:read` / `artifact:download` |
| Sessions create with `scope_id` | 403 if not member / no `sandbox:exec` (already) |
| Settings Team | Either map carefully to scopes **or** keep product-only and add a Scopes admin |

## 2. Architecture rules (freeze)

1. **Model is frozen** (`contracts/workspace_authz_grants.md`): `Principal → scope membership → grants`.  
2. **Sandbox / agent / hydrator / WorkspaceStore never hold GrantStore** — control plane only.  
3. **Path confinement is defense-in-depth**, not authz (D9/D10).  
4. **Never trust model-supplied `scope_id` / `grant` in tool args** — strip mass-assignment (WP-M7).  
5. **Existing scopes never re-bootstrap** — `_ensure_scope_binding` owner-bootstrap **only on create** (WP-M7 IDOR).  
6. **Fail closed** — empty principal, missing membership, missing grant → deny (`GrantDenied` / `NotScopeMember` → HTTP 403).  
7. **Principal from verified claims (D1)** — conflicting `X-Principal-Id` → 403; no production path with auth off + header principal.  
8. **MVP grant enum is closed** — do not invent parallel permission strings in product without extending the enum + contract.  
9. **`bootstrap_owner` grants the full MVP enum** to the creating principal.  
10. **Presign only after grant check** — object keys must not be guessable.  
11. **Outer product roles ≠ agent grants** — `owner|admin|member` on harnesses is a different RBAC plane; map explicitly if unified later.  
12. **Browser never calls GrantStore** — BFF + service JWT with `principal_id` (D1).

## 5. Acceptance criteria

### A. Durable store

- [ ] `GRANT_STORE=postgres` implements Protocol against `scope_memberships` / `scope_grants`
- [ ] Bootstrap reads env (or settings) — not hardcoded memory in staging
- [ ] Restart: same principal still passes `workspace:read` / `sandbox:exec` on owned scope
- [ ] Stranger still 403 after restart (no empty-store allow)

### B. Identity (with D1)

- [ ] Staging requires service JWT; principal from claims only
- [ ] Header/`claims` mismatch → 403
- [ ] No documented production profile with auth off for scoped sessions

### C. Session path (regression)

- [ ] New scope → `bootstrap_owner` full MVP enum
- [ ] Existing scope → never re-bootstrap; non-member denied
- [ ] Create / hydrate / sync still grant-gated
- [ ] Tool args cannot inject `grant` / `scope_id` / `scope:admin`

### D. HTTP grant matrix

- [ ] Workspace list/get use `workspace:read` via `require_grant`
- [ ] Put/sync/delete use `workspace:write`
- [ ] Presign uses `artifact:download` (or read — document one)
- [ ] Membership invite/revoke requires `scope:admin`
- [ ] Object keys not enumerable without grant

### E. Product honesty

- [ ] Outer Team UI either maps to scope grants with clear copy **or** stays product-only with “agent scopes” separate
- [ ] BFF proxies membership admin with user JWT → service JWT principal

### F. Explicitly out / later

- [ ] Fine-grained path ACLs inside a scope  
- [ ] Cross-tenant scope sharing  
- [ ] Capability tokens inside sandbox (prefer control-plane grants + short-lived VK for models)

## 6. Implementation order

1. **Close D1 principal** for staging scoped sessions (prerequisite trust).  
2. **Postgres `GrantStore`** — map ORM; unique membership/grant rows.  
3. **Bootstrap wiring** — honor `GRANT_STORE`; migrate memory → postgres in staging.  
4. **Restart + IDOR integration tests** against Postgres.  
5. **Wire `require_grant` on Workspace HTTP** as D9 API lands.  
6. **Membership admin API** — invite/revoke/list; enforce `scope:admin`.  
7. **Presign path** — `artifact:download` + non-guessable keys.  
8. **BFF + thin Scopes UI** (optional) — distinct from Settings Team mock.  
9. **Audit log** (optional D11.1) — who granted/revoked what.

Do **not** put GrantStore in the sandbox. Do **not** re-bootstrap existing scopes. Do **not** conflate product `admin` with `scope:admin` without an explicit mapping doc.

## 9. Definition of done

D11 is **done** when:

1. Staging uses **Postgres GrantStore**; memory is test/dev only.  
2. Shared scopes remain correct **across supervisor restart**.  
3. HTTP surfaces that touch files/memberships are **`require_grant`-gated**.  
4. `scope:admin` and `artifact:download` have at least one real enforcement path each.  
5. Principal trust meets D1 for those paths.  
6. Product Team UI does not silently pretend to be scope grants.

Then proceed to **D12** (subagents / HA), without re-litigating “who may touch a scope.”

```12:20:services/supervisor/src/supervisor/seams/providers/grant_store_factory.py
def create_grant_store(name: str | None = None) -> GrantStore:
    """Select store from ``GRANT_STORE`` or explicit name.

    Names: ``memory`` (default). Postgres adapter is a follow-on.
    """
    chosen = (name or os.environ.get("GRANT_STORE") or "memory").strip().lower()
    if chosen == "memory":
        return MemoryGrantStore()
    raise ValueError(f"unknown GRANT_STORE={chosen!r}")
```
