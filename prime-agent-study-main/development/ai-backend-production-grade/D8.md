# D8 — Approvals + budgets

**Status:** HITL broker + session budget tracker real; timeout/pre-invoke/UI/metering incomplete  
**Wave:** 3 (after D1 auth, D4 sessions/SSE, D5 metering path, D6 tool invoke gate; can harden in parallel with D7)  
**Depends on:** D1 (tenant-bound list/respond), D4 (SSE `approval_*` + session status), D5 (non-zero `cost_total` + optional VK spend), D6 (invoke path that can emit/gate approvals)  
**Goal:** Dangerous or harness-requested actions pause the session until a human responds (or timeout denies). Session (and optionally VK) spend caps stop runs when metered cost exceeds limits. Product UI lists pending approvals and shows honest cost — not mock Settings theater.

**Done means (north star):**

> An `ApprovalRequired` (runtime or pre-invoke tool gate) parks the session in `awaiting_approval`; mutating APIs return 409; BFF/UI can list and respond; overdue approvals expire via a production sweeper using manifest `on_timeout`. Session budget from harness `BudgetSpec` auto-stops when journaled cost exceeds the cap. VK `max_budget_usd` is either enforced on gateway spend or removed from claims. Browser never calls supervisor approvals/budget APIs directly.

## 1. Why D8 exists

D4 streams events. D6 can invoke tools. D5 can complete models. Without D8, “safe + cheap” is theater:

```text
Runtime / tool invoke
        │
        ├─ ApprovalRequired ──► ApprovalBroker ──► awaiting_approval
        │         │                    │
        │         │                    ├─ GET …/approvals
        │         │                    └─ POST /v1/approvals/{id}
        │         └─ journal/SSE approval_required | approval_resolved
        │
        └─ MessageEnd.usage.cost_total ──► session_index.total_cost
                                              │
                                              └─ BudgetTracker → budget_exceeded

Gateway VK max_budget_usd ──(stored)──✗── not checked on chat
Outer Settings Budget / cost chips ──mock──✗── no BFF
```

## 2. Architecture rules (freeze)

1. **`ApprovalBroker.request` never blocks workers** — persist pending; session may enter `awaiting_approval`; clients poll/SSE + respond.  
2. **Mutating session APIs refuse while `awaiting_approval`** — messages, tools/invoke, memory, subagents → **409** until respond or timeout resolution.  
3. **Two approval sources (both valid):**
   - **HITL-on-event** — runtime emits `ApprovalRequired` (harness `extension_ui_request` today).  
   - **Pre-invoke gate** — supervisor checks `require_approval` / sandbox policy **before** `ToolProvider.invoke` and creates a broker row (D6/D8).  
4. **`approval_default` on SandboxProfile** — `ask` (default) parks; `never` auto-picks an allow-shaped choice and journals resolved without awaiting.  
5. **Timeout is mandatory in production** — call `expire_due` on a scheduler; apply manifest `on_timeout` (`deny` \| `allow`); journal `ApprovalResolved`; clear session when no pending remain; `respond_ui` if harness warm.  
6. **Browser never hits supervisor approvals** — BFF + service cred (D1); same for budget errors.  
7. **Session budget is harness-owned** — `BudgetSpec` from manifest (and later product prefs); enforce via `BudgetTracker` on `session_index.total_cost`.  
8. **Cost must be metered upstream (D5)** — budgets that never see non-zero `cost_total` are dead code.  
9. **VK budget: enforce or drop** — either gateway accumulates spend vs `max_budget_usd` → `403 VIRTUAL_KEY_BUDGET_EXCEEDED`, or stop advertising the claim and document supervisor-only budgets. Prefer aligning mint amount to harness `max_cost_per_session` if both exist.  
10. **Soft overshoot allowed once** — post-`MessageEnd` record may complete the turn that crosses the cap; next send refuses. Document; optional pre-flight reserve is later.  
11. **Choice must be in `options`** (prod harden) — reject arbitrary strings; idempotent respond keeps first choice.  
12. **Multi-pending honesty** — session returns to `active` only when **zero** pending remain (or explicit “resolve all” product rule).  
13. **Sticky runtime for harness UI reply** — `respond_ui` is process-local; multi-replica needs sticky sessions or shared live bus (D4/D12).

## 5. Acceptance criteria

### A. Approvals lifecycle

- [ ] Runtime or pre-invoke creates pending row; session → `awaiting_approval` when `approval_default=ask`
- [ ] `GET …/approvals` returns pending; SSE shows `approval_required`
- [ ] `POST /v1/approvals/{id}` with choice ∈ options → `approval_resolved`; harness `respond_ui` when applicable
- [ ] Messages / tools/invoke return **409** while awaiting
- [ ] `approval_default=never` auto-resolves without parking
- [ ] Production sweeper: after `timeout_s`, status `timed_out`, choice from `on_timeout`, journal resolved, session cleared when no pending left
- [ ] Respond after timeout → clear error (404/409), not unhandled 500

### B. Pre-invoke tool gate (with D6)

- [ ] Manifest/catalog `require_approval` names (or sandbox danger class) emit broker request **before** provider body
- [ ] Invoke does not execute tool body until allow; deny → journaled failure / no side effect
- [ ] Optional: set/consume `approval_token` so invoke cannot skip the gate

### C. Budgets

- [ ] Gateway (or supervisor normalize) writes non-zero `cost_total` on real completions (D5)
- [ ] Crossing `max_cost_per_session` → status `budget_exceeded`; further send refused
- [ ] Session list/detail expose `total_cost` (D4) for BFF chips
- [ ] VK: enforce spend **or** remove `max_budget_usd` from product claims; if keep, mint uses harness session cap
- [ ] Settings Budget either persists into create/manifest path **or** is removed/disabled with honest copy

### D. Product / BFF

- [ ] BFF proxies list/respond approvals (D1 service cred)
- [ ] Test UI: pending prompt + options; Approve/Deny; send disabled while awaiting
- [ ] Status enums include `awaiting_approval`, `budget_exceeded`
- [ ] Cost chips use BFF rollup — no hardcoded mock `$` on live pages

### E. Multi-pending

- [ ] Documented rule: session stays `awaiting_approval` until pending count is 0 (recommended)

## 6. Implementation order

1. **Timeout sweeper** — background task / leader loop calling `expire_due`; wire journal + session clear + `respond_ui`; map timed-out respond errors on HTTP.  
2. **Fix `ApprovalSpec`** — parse `require_approval: string[]`; keep `on_timeout`.  
3. **Pre-invoke gate on `invoke_tool`** (D6) — before provider; reuse broker + awaiting.  
4. **Choice ∈ options + multi-pending session rule.**  
5. **D5 metering** — so `BudgetTracker` moves; integration test with stub cost.  
6. **VK enforce-or-drop** — single decision; align mint to harness cap if enforce.  
7. **Expose `total_cost` on session APIs** (D4 leftover).  
8. **BFF AiClient** — approvals + session message/status; map 409.  
9. **FE Test HITL + Settings honesty** — live approvals; budget prefs or disable tab.  
10. **Multi-replica** — sticky runtime or shared bus for `respond_ui` (may land in D12); sweeper lease.

Do **not** polish Settings monthly-budget notifications before sweeper + metering + BFF HITL.

## 9. Definition of done

D8 is **done** when:

1. Pending approvals **time out** in production with journal + session recovery.  
2. Configured tools **cannot** mutate before allow (pre-invoke or equivalent).  
3. BFF/UI can **list and respond**; Test chat respects `awaiting_approval`.  
4. Session budgets **trip on real metered cost**; cost visible on session APIs/UI.  
5. VK budget is **enforced or explicitly dropped** — no silent fake claim.  
6. Settings Budget is **wired or removed** — no monthly-cap theater.

Then proceed to **D9** (workspace), **D10** (sandbox), etc., without re-litigating HITL vs spend ownership.
