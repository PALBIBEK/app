# D6 — Tools execute

**Status:** AI plane scaffolding real; builtins mostly stubs; system↔AI tool identity unbound  
**Wave:** 2 (after D1–D5 vertical slice: auth, ready, catalog bind, sessions/SSE, gateway)  
**Depends on:** D1 (tenant-bound invoke), D2 (`run_allowed` before Test/Tools UI), D3 (pinned `tool_set` digests on composition), D4 (session lifecycle + journal `tool_start`/`tool_end`), D5 (model returns `tool_calls` into the agent loop)  
**Goal:** Session ToolSets actually run. Catalog builtins have real handlers (not only `echo`). Githi file tools (`read` / `write` / `ls`) honor the pinned ToolSet. System product tool UUIDs map into session ToolSets. MCP remains optional. Approvals + sandbox policy gate dangerous invokes.

**Done means (north star):**

> Builtins real; system tool IDs → session ToolSet; MCP optional. A composition-pinned session can list and invoke every tool in its ToolSet without `TOOL_NOT_IMPLEMENTED`. HTTP `POST …/tools/invoke` and the in-loop provider agree on outcomes; journal + outbox stay consistent for the RPC path.

## 1. Why D6 exists

D3 pins a ToolSet digest. D4 journals tool events. D5 can return `tool_calls`. Without D6, “tools” are theater:

```text
UI Tools / Harness Test
  → System BFF (D1/D2)
  → Supervisor session (D4)
  → ToolProvider.list_tools / invoke
        │
        ├─ CatalogToolProvider  ← composition bind (coding-tools / githi-tools)
        ├─ GithiToolProvider    ← githi runtime fallback (no composition seams)
        ├─ McpToolProvider      ← optional Composite overlay
        └─ NullToolProvider     ← empty bag
```

Until D6 closes:

| Today | Problem |
|-------|---------|
| `coding-tools` lists `bash`, `read`, `write`, `grep`, `git_commit`, `echo` | Only **`echo`** has an in-process handler |
| Composition + githi | `CatalogToolProvider` wins; `GithiToolProvider` never injects → file tools die with `TOOL_NOT_IMPLEMENTED` |
| System `/api/v1/tools` UUID CRUD | Never published into AI ToolSet digests |
| Harness `tools: UUID[]` | Product IDs ≠ catalog tool names |
| MCP | Adapter exists; not a product path; stdio / per-tool `provider_ref` out of scope |
| Approvals | Broker + HTTP real; harness `require_approval: []`; invoke path does not request approvals |

**UI surfaces that depend on D6**

| UI | Need |
|----|------|
| Harness **Tools** tab / product tool picker | UUID → name/schema → digest ToolSet on bind (with D3 publish) |
| **Test** chat tool chips | Real `tool_start`/`tool_end` with non-stub payloads |
| Tools invoke (lab) | BFF → `POST /v1/sessions/{id}/tools/invoke` |
| Approvals UX | List/respond when runtime emits `ApprovalRequired` |

## 2. Architecture rules (freeze)

1. **Production ToolSet = composition digests**, not harness YAML `tools:` — YAML is **recovery classification only** (`contracts/composition.md`, `contracts/harness_binders.md`).  
2. **`ToolProvider` is the only execute surface** — runtimes consume seams; they must not construct catalog/MCP concretes (P-3 / `contracts/seams.md`).  
3. **Browser never calls supervisor invoke** — BFF + service cred (D1); same ready gate as Run (D2).  
4. **`tool_start` before body** — unpaired start = unknown outcome (D4 / `AGENT_CONTRACT`).  
5. **HTTP invoke owns the supervisor outbox** — `session_id:tool_call_id` idempotency; Memory service has a **separate** outbox (ADR-004); do not cross-wire.  
6. **Sandbox profile gates file effects** on the RPC path (`SandboxPolicy.check_tool_invoke`); danger tools need `danger_full_access`.  
7. **Approvals are non-blocking on request** — `ApprovalBroker.request` returns immediately; session may enter `awaiting_approval`; mutating APIs refuse until respond/timeout.  
8. **MCP is optional** — compose via `MCP_SERVER_URL` / pin `mcp_server_url`; catalog tools win name collisions (`CompositeToolProvider` first-match).  
9. **System UUID ≠ tool name** — bind/publish must map product tool rows → ToolDefinition names + parameters before session create.  
10. **Custom HTTP tools** (system `endpoint`) are not free-form SSRF from the sandbox — supervisor-mediated invoke or MCP only.

**Bridge freeze**

```text
UUID system Tool  = authoring input (product DB)
```

| Mode | Behavior |

| **Pin-only (MVP)** | Bind composition that already pins `coding-tools` / `githi-tools`; system `tools[]` may be empty for Run |

**Lab execute** (if shipped): authz + re-validate SSRF at call time + timeout + rate_limit + active status; structured result; **not** a substitute for session invoke (no journal/chips).

## 4.2 Anti-patterns

1. Treat system UUID as LLM tool name — digests/names are runtime.  
2. Skip ToolSet publish and pass FE mock builtins into sessions.  
3. Mutate offered ToolSet in place — republish = new digest.  
4. Browser → `/v1/catalog` or `/v1/sessions/.../tools/invoke`.  
5. Lab execute as the agent loop — breaks traces/chips.  
6. Advertise ToolSet names without handlers (`bash` listed, only `echo` runs).  
7. Dual taxonomies without mapping (FE builtin/custom/mcp vs BE categories vs AI digests).  
8. Store MCP as fake system Tool rows with Python snippets — MCP is plug URL.  
9. SSRF only at create — re-check at Lab execute (DNS rebinding).  
10. Compose MCP + catalog without documenting first-wins collisions.
