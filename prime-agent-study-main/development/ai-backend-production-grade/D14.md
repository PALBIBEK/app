**Status:** In progress — closes LOCAL_DEMO checklist row 5 blocker

**Goal:** On a laptop, a bound `coding-v1` harness can create a session that starts a **real** Docker sandbox from a **built, digest-pinned** harness image — not a placeholder digest (`sha256:aaaa…`).

**Done means (north star):**

> Build `harness/images/Dockerfile` → pin the real image id into `coding-docker-v1` + `coding-v1.yaml` → recompute catalog digests → supervisor (with docker.sock) creates a session → `201` with an active sandbox. No soft-fallback to `local_process`. No leaving placeholder digests in shipped pins. Production multi-tenant remains `e2b` (D10); this Dn owns the **honest local_docker** path only.

## 1. Why D14 exists

D4 session create and LOCAL_DEMO row 5 fail live because shipped pins say:

```text
image_digest: sha256:aaaaaaaa…aaaaaaaa
```

That digest is a fixture, not an image on the machine. Docker cannot pull it. Acceptance tests still pass because they use in-memory / TrackingProvider sandboxes — they never prove the laptop image path.

```text
LOCAL_DEMO #5 / D4 create
        │
        ▼
coding-v1 → sandbox_profile coding-docker-v1
        │
        ▼
local_docker.create(image=image_digest)
        │
        ├── TODAY: placeholder aaaa… → pull fail → 503
        └── D14: real built image id → container up → 201
```

D10 already defines providers (`local_docker`, `e2b`, …). D14 does **not** redesign providers. It makes the **local_docker pin real**.

## 2. Architecture rules (freeze)

1. **No placeholder digests** in offered `coding-docker-v1` / `coding-v1` pins after PASS.  
2. **No soft-fallback** to `local_process` when digest is fake — fail closed or use a real image.  
3. **Build from harness root** per `harness/README.md` (`docker build -f images/Dockerfile …`).  
4. **Pin image identity** the supervisor actually runs (local image `Id` / `RepoDigest` as documented).  
5. **Same Docker daemon** as supervisor (`/var/run/docker.sock` mount on compose).  
6. **Recompute composition digests** after profile JSON changes (`npm run recompute-digests`).  
7. **Browser never talks to Docker** — BFF → supervisor only (D1).  
8. **e2b / MULTI_TENANT_STRICT** unchanged (D10) — out of scope for this Dn except “do not break.”  
9. Follow **D0**: blind tests + fresh verify subagent; implementer does not self-PASS.

- [ ] From `harness/`, image builds: `docker build -f images/Dockerfile -t pi-harness:coding-v1 .`  
- [ ] Real `sha256:…` (not all-`a` / all-`b` / REPLACE / PLACEHOLDER) recorded in:

  - `harness/versions/coding-v1.yaml` → `image_digest`
- [ ] Profile / composition digests recomputed and consistent with catalog verify  
- [ ] Documented one-liner in this guide or LOCAL_DEMO for rebuild + re-pin

### B. Live session create (Critical — LOCAL_DEMO #5)

- [ ] Supervisor ready with catalog loaded and docker.sock available  
- [ ] Bound harness using shipped `coding-v1` pins  
- [ ] `POST` session (BFF or supervisor) → **201** (not 503 image/placeholder failure)

- [ ] Blind suite asserts live/local image id is usable (inspect or create path)
