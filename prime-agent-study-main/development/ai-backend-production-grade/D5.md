# D5 — Model gateway

**Status:** PASS (2026-08-30) — verify cycle 2 scored 30/30; next scope D6  
**Wave:** 2 (after D1–D4 vertical slice; can harden in parallel with D2 readyz once auth exists)  
**Depends on:** D1 (service auth to gateway), D2 (gateway `/readyz` + compose healthy), D3 (`model_route` / plug_bindings on compositions), D4 (sessions expose cost; Test chat consumes real completions)  
**Goal:** Real model replies through the gateway with mandatory auth, real streaming, usage/cost metering, retries/fallback, and **vendor keys only in gateway secrets** — never in the browser, system plaintext Settings as theater, or sandbox env.

**Done means (north star):**

> Supervisor reaches configured providers via OpenAI-compat gateway. Auth fails closed. Streaming works for real providers. Every completion is metered; virtual-key budgets enforce or are explicitly supervisor-owned. Keys never leave the gateway process.

## 1. Why D5 exists

D4 makes Test chat real over SSE. Without D5, “real” often means **echo** or **502 missing key**, stream is fake, and cost chips stay `$0`.

```text
Browser ──user JWT──► System BFF ──service cred──► Supervisor
                                                      │
                                                      ├─ mint vk_… (service token)
                                                      └─ HttpModelGatewayClient(Bearer vk_ or GATEWAY_TOKEN)
                                                              │
                                                              ▼
                                                      model-gateway :8090
                                                              │
                                                              ├─ OPENAI_API_KEY / OPENROUTER_API_KEY (env only)
                                                              └─ upstream provider
```

**UI surfaces that depend on D5**

| UI | Need |
|----|------|
| Harness **Test** / Sessions chat | Real model text (not echo-only in staging) |
| Live token feel | Streaming deltas (or honest `message_end`-only) |
| Sessions / Traces **cost** | Non-zero usage from gateway → supervisor `total_cost` → BFF rollup (D4) |
| Settings **API Keys / Models / Budget** | Honest ops/BYOK story — not mock `sk-…` theater |
| Budget auto-stop | Supervisor budget + optional VK `max_budget_usd` |

## 2. Architecture rules (freeze)

1. **Vendor keys live in gateway env/secrets only** (`contracts/model_gateway.md`).  
2. **Browser never calls gateway** and never gets `NEXT_PUBLIC_*` vendor keys or gateway tokens.  
3. **System Settings UI** may later store **encrypted BYOK** and provision gateway — it must not become the chat path.  
4. **Sandbox** never receives `OPENAI_*` / `OPENROUTER_*` / `GATEWAY_TOKEN` / `MODEL_GATEWAY_*` — session **`vk_`** only if the agent must call gateway.  
5. **`model` on chat = gateway route id** (e.g. `githi`, `echo`), not raw vendor id unless the route table says so.  
6. **Gateway stays independent** — no `supervisor.*` imports.  
7. **Liveness ≠ readiness** — `/v1/healthz` cheap; `/v1/readyz` (D2) fails when non-echo routes lack credentials.

## 5. Target design for D5

### 5.1 Key custody

```text
ESO / secrets
  ├─ MODEL_GATEWAY_TOKEN      → gateway + supervisor (mint only)
  ├─ OPENROUTER_API_KEY       → gateway only
  └─ OPENAI_API_KEY           → gateway only

Supervisor (service token) ──mint──► vk_{session}
Runtime / (optional sandbox) ──────► chat with Bearer vk_
```

### 5.2 Streaming

| Layer | Target |
|-------|--------|
| Gateway | Upstream `stream=true` → OpenAI-compat SSE relay for real providers |
| `HttpModelGatewayClient.stream` | Parse `data:` lines; yield deltas; final usage on done |
| Githi / product | Emit live chunks when enabled; `message_end` still authoritative (D4 contract) |

### 5.3 Metering

1. Normalize upstream usage → `{input_tokens, output_tokens, cost_total}`.  
2. Persist or emit per `(tenant, session, route, status)`.  
3. On each chat: if VK has `max_budget_usd`, accumulate spend; overshoot → `403 VIRTUAL_KEY_BUDGET_EXCEEDED`.  
4. Supervisor continues journal budget from `MessageEnd.usage`; BFF list chips use D4 rollup.

### 5.4 Retries / fallback

Route meta example:

```json
{
  "githi": {
    "provider": "openrouter",
    "upstream_model": "anthropic/claude-sonnet-4",
    "retries": 2,
    "fallback_route_ids": ["githi-backup"]
  }
}
```

Retry only transient failures; surface stable error codes to supervisor.

### 5.5 Settings UI (product honesty)

| Option | Behavior |
|--------|----------|
| **A (MVP)** | Replace API Keys tab with “Providers configured by ops” + link to status |
| **B (BYOK)** | Encrypt keys on system → provision gateway → mask on GET; never return plaintext |

Models tab: proxy `GET /v1/routes` (no secrets). Budget tab: persist prefs → harness `BudgetSpec` / VK mint claims.

## 10. Definition of done

D5 is **done** when:

1. Staging/prod can run a **non-echo** route with keys in gateway secrets only.  
2. Auth is **fail-closed**; VKs are the session credential for chat.  
3. Streaming works end-to-end (gateway + supervisor client) **or** product explicitly ships `message_end`-only with docs.  
   **Shipped:** Test/githi uses `complete` + journal `message_end` (see `contracts/model_gateway.md` Product Test chat profile). Gateway provider SSE + `HttpModelGatewayClient.stream` remain available.  
4. Cost/usage reaches supervisor budgets and (via D4) UI rollups.  
5. Sandbox/harness cannot exfiltrate provider or service tokens.  
6. Settings UI no longer lies about storing provider keys unless BYOK is real.

Then proceed to **D6** (tools execute), **D7** (memory), etc., without re-litigating the LLM edge.
